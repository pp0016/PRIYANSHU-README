### Core Technical Highlights

1. **FFmpeg Cutting Strategy**:
   - **Command**:
     ```bash
     ffmpeg -ss <start_sec> -i "input.mp4" -t <duration_sec> \
       -c:v libx264 -preset fast -crf 18 -pix_fmt yuv420p \
       -c:a aac -b:a 192k -avoid_negative_ts make_zero -y "output/clip_X.mp4"
     ```
   - **Rationale**: Stream copy (`-c copy`) fails because H.264 keyframes occur every 2–8 seconds, leading to misaligned cuts, initial black frames, or audio drift. Re-encoding (`libx264`/`aac`) forces a new IDR keyframe at frame 0.0s of each clip, guaranteeing frame-accurate cuts and millisecond A/V sync.

2. **Per-Clip Audio Extraction**:
   - **Command**:
     ```bash
     ffmpeg -i "output/clip_X.mp4" -vn -acodec libmp3lame -ar 16000 -ac 1 -b:a 64k -y "output/clip_X.mp3"
     ```
   - **Rationale**: Compact audio files (~300–600 KB per clip) simplify Groq Whisper API requests and ensure returned word timestamps naturally start at `0.00s`.

3. **Groq Whisper Transcription & 3-Word SRT Algorithm**:
   - **Groq API**: Model `whisper-large-v3`, `response_format="verbose_json"`, `timestamp_granularities=["word"]`.
   - **Algorithm Rules**:
     - Chunk consecutive word objects into blocks of at most 3 words per line/block.
     - Block start = start time of 1st word in block ($S_{raw}$).
     - Block end = end time of last word in block ($E_{raw}$).
     - Strict non-overlap enforcement: $S_{adj}(B_k) = \max(S_{raw}(B_k), E_{adj}(B_{k-1}))$.
     - Millisecond time formatting: `HH:MM:SS,mmm`.
