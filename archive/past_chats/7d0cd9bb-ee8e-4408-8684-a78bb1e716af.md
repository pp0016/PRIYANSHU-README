### 🤖 Antigravity
The main difference between how the vidIQ and NexLev MCP bridges connect comes down to their **architecture**, **authentication**, and **stability** within this environment. 

Everything is actually "good" — they just use two different approaches to connect to their respective services!

Here is the breakdown of the differences:

### 1. Integration & Architecture
* **vidIQ Bridge**: It uses a custom, locally-hosted Python script (`vidiq_mcp_bridge.py`) that is hardcoded into your global `mcp_config.json`. Because it's perfectly integrated into the environment's config, the built-in `call_mcp_tool` command recognizes it instantly and natively.
* **NexLev Bridge**: NexLev runs via a Node package (`npx @nexlev-io/mcp-remote`). It acts more like a standalone background server connecting to NexLev's cloud. Because of how it binds to network ports (like port 28085), the built-in tools sometimes struggle to find it or connect to it properly.

### 2. Authentication Methods
* **vidIQ**: Uses a simple, static **API Key** passed as an environment variable (`VIDIQ_API_KEY`) directly in the configuration file. It's a silent, backend-only authentication.
* **NexLev**: Uses an interactive **OAuth token flow**. The very first time it runs, it pops open a browser window asking you to authorize it, and then caches those tokens locally (in `.mcp-auth`).

### 3. Stability & How I Call Them
* **vidIQ**: Works flawlessly with my standard, built-in tool (`call_mcp_tool`). No workarounds needed.
* **NexLev**: Because the `npx` server can sometimes leave "stale" processes running in the background and block the port, it often throws a `"server name nexlev not found"` error. To get around this and make it work perfectly, the `nexlev-mcp-caller` skill provides me with dedicated Python scripts (`nexlev_call.py` and `nexlev_batch.py`) that connect to the NexLev server directly using the official MCP Python SDK, completely bypassing the built-in tool's limitations. 

So, while vidIQ is cleanly integrated out-of-the-box, NexLev requires a slightly more "manual" bridge using custom scripts—but both are fully functional!
