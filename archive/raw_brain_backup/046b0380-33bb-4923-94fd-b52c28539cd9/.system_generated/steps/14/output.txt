For local Large Language Model (LLM) inference in 2026, the "minimum usable" speed depends entirely on your specific use case, though general consensus has coalesced around several clear tiers[1][2].

### **The "Usable" Tiers**
*   **< 10 tokens/s (Barely Interactive):** This is generally considered the lower bound for manual interaction[1][3]. It is often acceptable for slow, contemplative reading or tasks where you trigger a prompt and walk away, but it will feel sluggish for most conversational needs[1][4].
*   **10–20 tokens/s (Genuinely Usable):** Many users find this range to be the "minimum functional" threshold for interactive chat[1][2]. At this speed, the model generates text at roughly the same rate as a human reads, preventing the "waiting for text" frustration[1][2].
*   **30–40 tokens/s (Comfortable):** This is considered the "sweet spot" for most interactive tasks, including coding assistance and fast-paced Q&A[1][2][4]. It feels snappy and responsive[1][4].
*   **60–100+ tokens/s (High-Performance/Agentic):** This level of speed is preferred for heavy agentic workflows, rapid coding, or scenarios where you want the model to process large amounts of data without noticeable delays[1][2].

---

### **Why "Tokens per Second" (TPS) Isn't the Only Metric**
In 2026, experts emphasize that relying solely on TPS is misleading[1][5][6]. A high TPS figure can mask a poor user experience if the model is slow to begin responding[2][7]. You should evaluate three interconnected metrics for a true sense of performance[8][9]:

1.  **Time to First Token (TTFT):** Often more important than raw speed for user perception[5][10]. If this is high (e.g., > 1–2 seconds), the model will feel unresponsive regardless of how fast it generates subsequent text[1][5].
2.  **Tokens per Second (Generation Speed):** Measures the smoothness of the text stream[11]. This is the "reading speed" experienced during a conversation[11][7].
3.  **Prompt-Processing (Prefill) Speed:** Crucial if you frequently feed the model large documents or long context windows[1][12]. A slow prefill speed will cause significant "hang time" before the model even begins to think[13][14].

### **Practical Advice for 2026**
*   **Size Matters:** The most common mistake is running a model too large for your hardware[15]. A smaller, properly quantized model that runs at 40+ tokens/s will almost always provide a better experience than a massive model crawling at 3 tokens/s[15][16].
*   **Quantization:** Using Q4 (4-bit) quantization is now the industry standard for local inference[17]. It typically offers the best balance between maintaining model "intelligence" and achieving the high memory bandwidth required for fast token generation[17][18].
*   **Hardware Context:** If you are using CPU-based inference, pay close attention to memory bandwidth (e.g., multi-channel RAM), as this is usually the primary bottleneck for local performance[19][12].
