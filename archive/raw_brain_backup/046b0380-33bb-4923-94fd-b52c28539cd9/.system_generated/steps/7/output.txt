For running LLMs locally with tools like **llama.cpp** and **Ollama**, VRAM is the most critical hardware constraint[1][2]. It acts as a hard limit: if a model and its required context (KV cache) do not fit entirely into VRAM, performance drops significantly as the system spills over into slower system RAM[1][3].

### **VRAM Capacity & Model Capability (2025/2026 Standards)**
The following table summarizes the general capacity of RTX-class GPUs to handle models (typically using **Q4_K_M quantization**, which is the industry standard for balancing speed, quality, and memory)[4][5][6].

| VRAM | Typical Use Case | Recommended Models |
| :--- | :--- | :--- |
| **8GB** | Entry-level / Baseline | 7B–9B parameter models (e.g., Llama 3.1 8B)[1][4][7] |
| **12GB** | Balanced / Good for 14B | 7B–14B models (e.g., Qwen 2.5 14B)[1][4] |
| **16GB** | Prosumer / Developer | 14B–20B models; comfortable context for 8B models[1][7] |
| **24GB** | High-end Consumer | 30B–35B models; 8x7B MoE models[1][4][5] |

### **Performance Expectations (Tokens Per Second)**
Tokens per second (TPS) during "decode" (generation) is primarily **memory bandwidth-bound**[8][9]. Higher-end cards with more bandwidth (e.g., RTX 3090/4090 vs. 4060) will naturally yield higher TPS[10][11].

*   **8GB VRAM (e.g., RTX 4060):** You can expect roughly **20–30 TPS** on 8B models[12].
*   **16GB VRAM (e.g., RTX 4070 Ti Super / 4080):** Often reaches **50–80+ TPS** for 8B models due to higher bandwidth[13][12].
*   **24GB VRAM (e.g., RTX 3090 / 4090):** These cards are the "sweet spot." An RTX 4090 can achieve **100+ TPS** on 8B models and remains performant for much larger models[9][12].
*   **Next-Gen (e.g., RTX 5090):** Benchmarks show significant gains (up to 200+ TPS for 8B models) primarily due to superior memory bandwidth (GDDR7)[9][6].

### **Key Factors Affecting Performance**
*   **Quantization:** Using **Q4_K_M** is highly recommended[1][5]. It provides a 75% reduction in VRAM usage compared to FP16 with minimal quality loss[5].
*   **Context Window:** The KV cache (memory required to remember the conversation) grows linearly with context length[6]. If you increase context to 32K or 64K tokens, your VRAM requirements will increase by 1–2+ GB, which may force you to use a smaller model or higher quantization[1].
*   **Inference Engine:** 
    *   **llama.cpp** and **Ollama** share the same core engine, so performance is nearly identical when configured with the same settings[14][15]. 
    *   If you require high-concurrency (serving many users at once), tools like **vLLM** are generally faster, but for single-user local chat, the difference between these runners is negligible compared to hardware limits[16][14].
*   **The "Rule of Thumb":** If it fits in VRAM, it runs fast. If it doesn't fit, it runs on the CPU/RAM, which will result in "crawling" speeds (often < 1–5 TPS)[1][17][3].
