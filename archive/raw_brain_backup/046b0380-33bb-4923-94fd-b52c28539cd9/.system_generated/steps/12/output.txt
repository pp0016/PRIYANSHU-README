The search for "Llama 4 Scout Maverick VRAM requirements local inference quantized GGUF 2025" returned the following summary:
Running **Llama 4 Scout** and **Llama 4 Maverick** locally requires accounting for their Mixture-of-Experts (MoE) architecture, where the total parameter count is high, but the active parameters per token remain 17B[1][2][3]. Because every expert’s weights must reside in VRAM to be available, memory requirements are determined by the total parameter size rather than the active parameter count[1].

### VRAM Requirements Summary
Quantized GGUF versions significantly reduce these requirements compared to full-precision weights[4]. Below are the approximate VRAM needs for common quantization levels.

| Model | Total Params | 1.78-bit (IQ1_S/M) | ~2.4-bit (IQ2_XXS) | ~4-bit (Q4_K_XL) |
| :--- | :--- | :--- | :--- | :--- |
| **Llama 4 Scout** | 109B[4][5] | ~34 GB[4][2] | ~39 GB[4] | ~66 GB[4] |
| **Llama 4 Maverick** | 400B[4][5] | ~122 GB[4][2] | ~140 GB[4] | ~200 GB+[2] |

*Note: These estimates are for model weights; additional VRAM is required for the KV cache, which scales with your context length[1].*

---

### Key Considerations for Local Inference

*   **Scout (109B):** Can be run on high-end consumer hardware with quantization[4][6]. The 1.78-bit GGUF versions can fit into ~34 GB of VRAM, making them potentially runnable on dual 24GB GPU setups (like 2x RTX 4090s)[4]. 
*   **Maverick (400B):** Requires significantly more substantial hardware[7]. To run quantized Maverick (e.g., 1.78-bit or 2-bit), you generally need a multi-GPU setup with at least **128GB+ of combined VRAM/RAM**[4][8]. 2x 48GB GPUs (or 4x 32GB/40GB cards) are commonly suggested for efficient local execution[4][8].
*   **Dynamic GGUFs:** Unsloth provides "dynamic" GGUF files that selectively quantize layers (e.g., keeping attention layers at 4-bit or 6-bit while using lower bits for MoE layers)[4]. This approach is highly recommended to maintain better performance and accuracy than standard uniform quantization[4][8].
*   **Context Window:** While Scout supports a 10M token context window, running at this length locally is extremely memory-intensive[1][9]. The KV cache size will increase drastically with context; if you encounter "Out of Memory" errors, reducing the effective context length is the first step[1].
*   **Hardware Choice:** Apple Unified Memory (Mac Studio/Pro) is often a viable alternative for these models due to the large memory capacity available compared to traditional multi-GPU PCIe configurations[8].
