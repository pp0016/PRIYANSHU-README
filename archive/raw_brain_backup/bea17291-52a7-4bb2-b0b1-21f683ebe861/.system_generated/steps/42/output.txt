No, you cannot combine the RAM of two Macs to create a single, larger pool of memory for a single application.

This is a common point of confusion, but it is important to distinguish between **distributed computing** and **shared memory**.

### Why you cannot "combine" RAM
*   **Physical Isolation:** RAM is hardware that is physically connected to the processor of a specific computer via high-speed buses. There is no standard consumer technology that allows one computer to access the physical RAM sticks or memory chips of another computer over a network (like Wi-Fi or Thunderbolt) with the speed required for standard application memory.
*   **Latency:** Even if you could bridge memory over a network, the speed of network communication is orders of magnitude slower than the speed at which a processor accesses its own local RAM. If an application attempted to use this "combined" memory, it would perform so slowly that the system would effectively grind to a halt.

### What Docker Swarm and Kubernetes actually do
Tools like **Docker Swarm** and **Kubernetes** are **container orchestrators**. They are designed to manage multiple computers (nodes) as a cluster, but they **do not aggregate RAM or CPU** into a single pool.

*   **Load Balancing and Scheduling:** Instead of merging hardware, these tools allow you to break an application into smaller, independent pieces (containers or services).
*   **Distribution, Not Aggregation:** The orchestrator decides which computer has enough *available* resources (CPU and RAM) to run a specific container. It might run "Service A" on your MacBook and "Service B" on your iMac.
*   **Scaling:** If you have an application that can be run in parallel (like a render farm, a web server, or a data processing pipeline), you can deploy multiple replicas of that application across both machines. This increases your *total* processing capacity, but each individual replica is still limited by the RAM available on the specific Mac where it is currently running.

### Summary of Options
*   **If you need more RAM for a single heavy task:** The only solution is to physically upgrade the RAM in that specific computer (if the model allows it) or use a machine with more memory.
*   **If you are doing parallel work (e.g., video rendering or simulations):** You can use Docker Swarm or Kubernetes to distribute different parts of your workload across both Macs. Each Mac will work on its own portion of the task, using its own local RAM, and then the results can be aggregated at the end.
