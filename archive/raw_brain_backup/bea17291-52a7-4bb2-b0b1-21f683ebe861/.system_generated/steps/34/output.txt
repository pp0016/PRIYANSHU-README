RDMA (Remote Direct Memory Access) over Thunderbolt is a feature introduced in **macOS 26.2** that enables high-performance, low-latency, peer-to-peer communication between Mac computers[1][2].

### Key Compatibility and Requirements
*   **Hardware Requirement:** RDMA over Thunderbolt is specifically designed for and restricted to **Thunderbolt 5** hardware[1][3][4]. 
*   **Thunderbolt 3/4 Support:** There is **no official support** for RDMA over Thunderbolt on Thunderbolt 3 or Thunderbolt 4 controllers[5][6]. Users attempting to use this feature on M3-series or other devices equipped with Thunderbolt 4 controllers have reported that the necessary kernel extensions and interfaces (such as `rdma_en*` devices visible via `ibv_devices`) do not load or function[7][6].
*   **Software Requirement:** The feature requires **macOS 26.2 or later**[1][3].

### How it Works
*   **Purpose:** The technology allows Macs to bypass the standard networking stack (TCP/IP), enabling direct memory access between connected computers[2][4]. This significantly reduces latency—reportedly dropping from ~300 microseconds to under 10 microseconds—and is primarily used to enable memory pooling and tensor parallelism for distributed AI workloads using frameworks like MLX[8][9][4].
*   **Enabling the Feature:** On supported Thunderbolt 5 hardware, the feature must be enabled via macOS Recovery mode by running `rdma_ctl enable` in the Terminal[1][3]. Once enabled, compatible interfaces can be verified using the `ibv_devices` command[1][10].

### Summary for Users
If you are looking to cluster Macs for high-performance tasks like local AI inference, this feature is currently exclusive to Apple Silicon Macs equipped with **Thunderbolt 5** ports[1][4]. Attempting to use this on Thunderbolt 4 systems will not yield the expected RDMA functionality[5][6].
