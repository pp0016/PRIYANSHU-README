JACCL (Jack and Angelos' Collective Communication Library) is an open-source collective communication library integrated into the **MLX** ecosystem, specifically designed to enable low-latency distributed machine learning (training and inference) across Apple silicon Mac clusters using **RDMA over Thunderbolt**[1][2][3].

### Key Information
*   **Purpose:** It provides high-speed, low-latency communication (sub-50 microsecond latency and 50–60 Gbps throughput) by bypassing the standard network stack, allowing multiple Macs to function as a unified cluster for tasks like tensor parallelism[1][2][3].
*   **Integration:** It is natively supported in **MLX**[4][5]. You can typically utilize it by setting the backend in distributed configurations, such as `mx.distributed.init(backend="jaccl")` or using the `--backend jaccl` flag with `mlx.launch`[6][7][8].
*   **Where to find it:** 
    *   **Core Logic:** JACCL is part of the main **[ml-explore/mlx](https://github.com/ml-explore/mlx)** repository[2][9].
    *   **Community Resources:** There are several community-maintained repositories and discussions on GitHub related to setting up JACCL clusters, such as [alexziskind1/mlx-jaccl-cluster](https://github.com/alexziskind1/mlx-jaccl-cluster)[10][11].
    *   **Go Bindings:** A Go-based implementation/wrapper exists at [tmc/gojaccl](https://github.com/tmc/gojaccl)[12][13].

### Troubleshooting & Usage Tips
*   **RDMA Setup:** RDMA must be manually enabled on macOS (typically via `rdma_ctl enable` in Recovery mode)[14][15].
*   **Common Pitfalls:**
    *   **RDMA Interface Ephemerality:** RDMA device names (e.g., `rdma_enX`) can change after reboots, requiring configuration updates[6].
    *   **Topology:** Ensure all machines in the cluster are properly connected via Thunderbolt 5 cables in a valid topology[15].
    *   **Lifecycle Issues:** Users have reported issues with consecutive send/recv operations or "session" exhaustion; these are often tracked as issues in the main `ml-explore/mlx` repository[16][17][18].
    *   **MLX Launch:** Avoid wrapping `mlx_lm share` inside `mlx.launch`, as it has its own built-in launcher[6].
