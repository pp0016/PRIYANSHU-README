The search for ""distcc" macOS "Mac mini" "MacBook" compile cluster" returned the following summary:
Setting up a `distcc` cluster on macOS (e.g., between a MacBook and a Mac mini) is technically possible for command-line builds, but it comes with significant caveats, particularly regarding modern Apple development workflows.

### Important Considerations
*   **Xcode Incompatibility:** `distcc` is **not natively compatible with Xcode** projects. While it works well with command-line build systems like `make`, `ninja`, or `xmake`, attempts to use it with Xcode typically result in build failures. There have been community efforts to patch this, but none are officially supported or integrated.
*   **Compiler Parity:** All machines in your cluster must use the **exact same version** of the compiler (e.g., Clang/LLVM). If versions differ, you risk undefined behavior or subtle compilation errors.
*   **"Pump" Mode:** While `distcc` supports a "pump" mode for distributed preprocessing, it is often deprecated or fragile in modern environments. Most users rely on standard mode, where the client performs preprocessing locally.

### Setup Guide (Command-Line Focus)

If you are using command-line tools and still wish to proceed, here is the general workflow:

#### 1. Installation
Install `distcc` on all participating Macs using Homebrew:
```bash
brew install distcc
```

#### 2. Configure the Server (Workers)
On the Mac mini or any machine acting as a worker, you must start the `distccd` daemon. Replace the IP range with your local network subnet:
```bash
# Start the daemon to listen for requests
brew services start distcc
# Or run manually to specify allowed IPs
distccd --daemon --allow 192.168.1.0/24
```

#### 3. Configure the Client (Master)
On your primary machine (e.g., MacBook), define the available workers in your environment:
```bash
# Example for ~/.bashrc or ~/.zshrc
export DISTCC_POTENTIAL_HOSTS="localhost 192.168.1.50 192.168.1.51"
```
*Note: Always include `localhost` and place the fastest machines at the beginning of the list.*

#### 4. Build Configuration
For systems like `make`, you can trigger distributed builds by setting the compiler variable:
```bash
# Example
make -j$(nproc) CC=distcc
```

### Modern Alternatives
Because `distcc` has seen limited development for macOS-specific workflows in recent years:

*   **`ccache`:** If your goal is simply to speed up repeated builds, `ccache` is often far more effective and less prone to configuration headaches. It caches build results locally, meaning subsequent compilations can be nearly instantaneous. Many developers use `ccache` in combination with `distcc` for maximum impact.
*   **Xmake:** If you are open to switching build systems, `xmake` has built-in distributed compilation support that is more modern and platform-agnostic than `distcc`.
*   **Apple's Distributed Build (Legacy):** Be aware that features like Apple's historical "Distributed Builds" in Xcode are long-deprecated and no longer functional for modern development.

**Recommendation:** If you are building standard C/C++ command-line projects, `distcc` can provide a speed boost if managed carefully. If you are building iOS/macOS apps within Xcode, you will likely find that the effort to patch and maintain a `distcc` environment outweighs the performance benefits, and you would be better served by optimizing your local build with `ccache` and ensuring your machine has sufficient RAM and SSD speed.
