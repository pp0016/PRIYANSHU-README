`rdma_ctl` is a command-line utility used in macOS (starting with version 26.2) to enable **Remote Direct Memory Access (RDMA) over Thunderbolt**[1][2]. This feature allows for high-performance, low-latency, peer-to-peer communication between Mac computers equipped with Thunderbolt 5 ports[1][3][4].

### How to Enable RDMA over Thunderbolt
Because this feature involves direct memory access, it requires a security-conscious setup process via macOS Recovery[3][5]:

1.  **Boot into macOS Recovery:** Shut down your Mac, then hold the power button for 10 seconds until the startup options appear[3]. Select **Options** to enter Recovery mode[3].
2.  **Open Terminal:** Once in Recovery, go to the top menu bar, select **Utilities**, and open **Terminal**[6][3].
3.  **Run the Enable Command:** Type the following command and press Enter[7][3]:
    ```bash
    rdma_ctl enable
    ```
4.  **Reboot:** Restart your Mac to return to the standard macOS environment[1][6].

### Verification and Usage
*   **Verify Status:** Once back in macOS, you can check if RDMA is enabled by running `rdma_ctl status` in the Terminal[8].
*   **List Devices:** Use the `ibv_devices` command to see the Thunderbolt interfaces that are ready for RDMA (e.g., `rdma_en2`, `rdma_en3`)[1][6][2].
*   **Network Configuration:** Simply enabling `rdma_ctl` is often not enough to get clusters working. You must also configure the network interfaces correctly (e.g., assigning IP addresses to the Thunderbolt ports and disabling the default "Thunderbolt Bridge" to prevent network loops or conflicts)[3][9][10].

### Requirements
*   **macOS Version:** macOS 26.2 or later[1][2].
*   **Hardware:** Apple Silicon Macs with **Thunderbolt 5** ports (e.g., M4 Pro Mac mini, M4 Max Mac Studio/MacBook Pro, or M3 Ultra Mac Studio)[1][3][11].
*   **Cables:** You must use cables that officially support Thunderbolt 5[12][3].

This functionality is primarily used by developers and power users for distributed computing tasks, such as running large AI models (e.g., via *exo* or *MLX*) across a cluster of Mac computers by pooling their memory and processing power[7][13][4].
