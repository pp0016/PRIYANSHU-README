RDMA (Remote Direct Memory Access) over Thunderbolt is a feature introduced in **macOS 26.2** that allows for low-latency, peer-to-peer communication between Apple Silicon Macs equipped with **Thunderbolt 5** ports[1][2][3]. By bypassing the standard OS network stack, it enables high-performance distributed computing, such as running large-scale AI models across a cluster of Macs[4][5][6].

### How to Enable RDMA
The `rdma_ctl` command is used to manage this feature. Because it bypasses normal security entitlements, it must be enabled locally on each machine in the cluster while in **macOS Recovery** mode[7][8][9].

1.  **Enter Recovery Mode:** Shut down your Mac. Hold the power button until the boot menu appears, then select "Options"[1][7].
2.  **Open Terminal:** Navigate to the Utilities menu and select **Terminal**[1][3].
3.  **Enable RDMA:** Run the following command:
    ```bash
    rdma_ctl enable
    ```
4.  **Reboot:** Restart your Mac back into the normal macOS environment[10][3].

### Verification
Once enabled, you can verify that the RDMA interfaces are active by running the following command in the Terminal:
```bash
ibv_devices
```
This should list your available RDMA-capable Thunderbolt interfaces (e.g., `rdma_en2`, `rdma_en3`)[3][9].

### Key Requirements & Caveats
*   **Hardware:** Requires Apple Silicon Macs with **Thunderbolt 5** ports[1][2]. While older Apple Silicon machines (M1/M2/M3) can participate in clusters, they will fall back to standard TCP/IP transport, which significantly reduces performance[7].
*   **OS Version:** Requires **macOS 26.2** or later[7][9].
*   **Cabling:** Use cables that support Thunderbolt 5 for optimal mesh connectivity[1][7].
*   **Security:** This configuration cannot be performed remotely; physical access to each machine is required[7][11].
*   **Use Case:** This technology is primarily used for distributed inference and machine learning workloads (e.g., via frameworks like **MLX** or tools like **Exo**) to share memory pools across multiple machines with significantly lower latency compared to standard networking[4][12][13].
